# 状态、反馈、实时刷新与动效

医院软件最常见的体验事故不是"不好看"，而是**数据刷掉了用户正在做的事**。本文件是所有状态与实时行为的强制要求。

## 1. 六种必备状态

任何数据区域都必须设计：`Loading`、`Empty`、`Error`、`Success`、`Disabled`、`Permission`；离线/连接异常场景再加 `Offline`。**没有这六种状态的页面视为未完成。**

### 1.1 空状态（Empty）

- 不显示空白页；居中图标（48px，辅助色）+ 主文案（14px）+ 副文案（12～13px）+ 可选操作。
- 文案必须说明**当前状态**而非"无数据"：`暂无待处理任务` / `当前没有需要处理的业务` / `本月暂无维修记录`。
- 有刷新价值时提供 `[刷新]` 按钮；筛选无结果时提供 `[清除筛选]`。

### 1.2 加载状态（Loading）

- 避免整页白屏：首屏用 Skeleton（骨架行），局部刷新用局部 Loading（`正在加载数据…` + 转圈）。
- 骨架块尺寸必须与真实内容接近，避免加载完成时大跳变。
- 数据到达后**平滑替换**，不做整块闪烁（不加 `animation: blink` 之类）。
- 超过 3 秒未返回时补充说明文字（`正在加载，请稍候…`），超过 10 秒提供 `[重试]`。

### 1.3 错误状态（Error）

- 结构：图标 + `发生了什么` + `下一步能做什么` + 操作按钮。
- 例：`暂时无法获取数据` / `请检查系统连接后重试。` / `[重新连接]`。
- 禁止裸 `Error`、`失败`、堆栈文本、英文异常码直接暴露给医院工作人员（技术码可折叠在"详情"里）。
- 局部失败不影响其它区块：一个卡片取数失败不能让整页报错。

### 1.4 成功状态

- 操作成功用 Toast 或就地状态变化反馈；禁止只靠"界面某处悄悄变了"暗示成功。
- 批量操作汇报结果数量（`已处理 12 条，2 条失败`），失败项可查看。

### 1.5 禁用与权限（Disabled / Permission）

- 无权限：**优先隐藏或禁用**，绝不"显示后点击报错"；必须显示时用锁定图标 + 悬停/点击给出无权限说明。
- 禁用：视觉降饱和 + 不可点，并在邻近位置说明原因（`需先选择科室`）。

### 1.6 离线 / 连接异常（Offline）

- 工作台常驻系统状态：`HIS ●正常 最后同步 17:32:18`；异常时 `HIS ●连接异常 最后成功同步 17:30:12 [重新连接]`。
- 断连期间禁用依赖远端数据的操作，并保留本地可用功能；恢复后自动补同步并给出轻提示。

## 2. 通知分级

| 级别 | 形态 | 示例 |
|---|---|---|
| 普通通知 | 右上角轻量提示，2～4 秒消失 | 保存成功、已复制 |
| 重要通知 | Toast + 导航 Badge 计数 | 新维修单、待审批增加 |
| 异常 | 明显提示，可留驻但不持续弹窗 | 同步失败、接口超时 |
| 紧急业务 | 按业务需要弹窗 | 需要立刻处置的告警 |

原则：**弹窗不得打断用户正常工作**；同一错误在短时间内只提示一次，不反复弹。

## 3. 新数据与实时刷新

后台数据变化（新增申请、新维修单、新报修、新移库单）时的正确链路：

```
后台数据变化 → 状态更新 → 列表增量更新 → Badge 变化 → 轻量通知
```

- **不整页刷新**；只更新变化行，并对新行做一次性轻微高亮（600～900ms 后恢复）。
- **用户当前打开的详情不因后台刷新而自动关闭。**
- 用户正在编辑的字段不被远端数据覆盖；冲突时保留本地输入并提示 `该记录已被他人修改`。

## 4. 自动刷新禁忌

存在自动轮询/推送时，必须逐条确认没有下列问题：

| 禁忌 | 判定 |
|---|---|
| 页面闪烁 | 刷新时整块重绘、白屏一瞬 |
| 滚动位置跳动 | 刷新后列表回到顶部 |
| 输入框内容丢失 | 用户输入被模板重渲染清空 |
| 当前详情关闭 | 抽屉被刷新逻辑关闭 |
| 编辑数据被覆盖 | 用户未保存内容被服务端值替换 |

正确做法：**静默刷新 + 增量更新**（保留滚动位置与焦点，diff 后只改变化节点）。

## 5. 反馈时机

| 操作 | 反馈 |
|---|---|
| 立即完成（<100ms） | 无需 loading，直接结果 |
| 100ms～1s | 按钮进入 loading，禁止重复提交 |
| >1s | 按钮 loading + 进行中说明或进度 |
| 批量操作 | 进度或结果汇总（成功/失败条数） |
| 危险操作 | 二次确认，说明后果（`删除后不可恢复`） |

## 6. 动效清单

允许：页面淡入、Drawer 滑入、Toast 出现/消失、Badge 数字变化、新数据轻微高亮、按钮悬停/按压反馈。

禁止：大面积飞入、长时间动画（>300ms 的常规交互）、高频闪烁、强烈弹跳、炫酷转场、无限循环动画（加载指示器除外）、以及"为了高级感"的视差/粒子/玻璃拟态动效。

时长与曲线见 `design-tokens.md` §6。整体感受必须是**稳定**：用户数小时使用不应被动画干扰。

## 7. 长时使用与隐私

- 避免纯白高亮（`#FFFFFF` 大面积）、过高对比、过多鲜艳颜色、过小字体、过密布局、频繁弹窗。
- 默认浅灰背景 + 白卡片，让眼睛有落点；每屏保留呼吸空间。
- **最小必要信息**：不主动显示患者身份证、手机号、地址、无关病历/个人信息；敏感字段脱敏（`张**`、`138****1234`），需要时通过权限与操作留痕再展示完整值。
- 涉及患者信息的查看/导出操作应留下审计痕迹（谁、何时、看了什么），并在界面上明确这是敏感操作。
