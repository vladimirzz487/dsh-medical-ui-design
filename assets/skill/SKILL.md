# 医院软件桌面端 UI 设计规范（Medical Desktop UI）

面向医院内部信息化软件的桌面端界面设计与改版：HIS 配套工具、医疗设备管理、医学装备管理、卫材库房、物资管理、维修管理、医院内部工作台、数据监控工具、业务辅助工具（WPF / Electron / Tauri / Web Desktop 均可）。

**核心目标**：把功能型、数据型、后台型医院软件做成简洁、专业、清晰、高效、能连续使用数小时的**桌面工作台**；不是营销网站，也不是炫技大屏。

---

## 0. 触发场景与第一步动作

| 场景 | 第一步动作 |
|---|---|
| **新增页面** | 先判定页面类型（工作台 / 列表 / 详情 / 表单 / 统计），从 §4 取配方，再套 §2 外壳与 §3 token |
| **新增/改动功能** | 先回答 §1 的业务四问，再决定它进入导航的哪一层、放在首页还是二级页、是否需要详情抽屉 |
| **调整页面布局** | 先核对 §5 信息层级（一级/二级/三级信息），保持外壳不变；只动主工作区，不动左导航与顶栏结构 |
| **加字段 / 改表格列 / 改表单** | 套 §6 表格原则与 §7 表单规格；判断字段是否属于最小必要信息（§9 隐私） |
| **界面改版 / UI 走查 / 风格统一** | 用 §12 清单逐条走查，并运行 §13 的合规审查脚本 |

任何场景下都不要重造设计系统：**先复用现有组件与 token，再谈新增**。

---

## 1. 核心设计原则（铁律）

1. **效率优先**：UI 的第一目标是让工作人员快速找到信息、理解状态、完成操作。绝不为了视觉效果牺牲信息获取速度、操作路径、数据可读性、状态识别、错误预防、长时间使用舒适度。
2. **工作台优先，不是传统管理后台**：不要"菜单 → 菜单 → 菜单 → 复杂表格"。应当"导航 → 工作台 → 核心任务 → 快速处理"。
3. **打开即知**：用户进入软件后应立刻知道——当前系统状态、当前要处理什么、有多少待处理、最近发生了什么、下一步做什么。
4. **业务四问**（设计任何页面前先答）：谁使用？每天最常做什么？最重要的信息是什么？最重要的操作是什么？
5. **少一点装饰，多一点信息；少一点操作，多一点直达；少一点炫技，多一点稳定；少一点复杂，多一点清晰。**

## 2. 默认外壳：左导航 + 顶部状态栏 + 主工作区

```
┌──────────────────────────────────────────────────────┐
│                    顶部状态栏 56～68px               │
├──────────────┬───────────────────────────────────────┤
│ 左侧导航     │            主工作区域                 │
│ 210～240px   │                                       │
│              │                                       │
│ ● 系统正常   │                                       │
└──────────────┴───────────────────────────────────────┘
```

- **左导航（210～240px，不可更宽）**：只承担**页面级导航**，不塞功能。结构：Logo/产品名 → 导航项 → 底部系统状态。一级导航 **4～7 项**，超过 7 项就改为「分组 + 二级菜单」（如 业务管理 / 物资管理 / 系统）。
- **顶栏（56～68px）**：左侧当前页面标题；右侧只放系统状态、通知、当前用户、设置。**不要塞一排按钮。**
- **主工作区**：页面背景 `#F5F7FA`，内容用白色卡片分区。页面主要留白 24px，卡片内边距 16～24px，组件间距 12～20px。
- 设计目标分辨率 **1920×1080**，同时必须兼容 **1366×768**；窗口缩放、表格宽度、侧栏、内容区、抽屉、弹窗都要检查。窗口变窄时的收窄顺序：减少装饰 → 压缩间距 → 减少次要信息 → 表格横向滚动。**绝不把桌面端压成手机布局。**

## 3. 设计 Token 速查（唯一来源，禁止临时造色/造字号）

| 类别 | 值 |
|---|---|
| 主色 Primary | `#2563EB`（医疗蓝，可按项目调整，但全项目唯一） |
| 成功 Success | `#16A34A` ｜ 警告 Warning `#F59E0B` ｜ 危险 Danger `#DC2626` ｜ 信息 Info `#2563EB` |
| 页面背景 / 卡片 / 边框 | `#F5F7FA` / `#FFFFFF` / `#E5E7EB` |
| 文字：主要 / 次要 / 辅助 | `#1F2937` / `#6B7280` / `#9CA3AF` |
| 字号：页面标题 / 模块标题 / 正文 / 辅助 | 20～24px / 16～18px / 14px / 12～13px（**正文不得小于 12px，且不得大量使用 12px 正文**） |
| 间距体系 | 4 / 8 / 12 / 16 / 20 / 24 / 32px（4px 基准） |
| 圆角：按钮·输入框 / 卡片 / 抽屉 | 6～8px / 8～12px / 12～16px |
| 阴影 | 极轻；**优先用 1px 边框而不是大阴影** |
| 表格行高 | 44～52px，中等数据密度，避免过度留白也避免一屏几十行 |
| 抽屉宽度 | 450～600px |

字体、状态色语义、完整 token 表与 CSS / XAML 变量定义见 `references/design-tokens.md`。
主题模板可直接复制：`templates/tokens.css`（Web）、`templates/theme.xaml`（WPF）。

**视觉风格关键词**：专业、克制、清晰、稳定、可信、高效、现代、医疗信息化。要让人感觉"这是医院工作人员每天用的专业工作软件"。

氛围要求：浅灰背景 + 白卡片 + 轻边框 + 轻阴影 + 克制状态色。**不使用**大面积渐变、强烈纹理、花哨背景、大面积装饰图片；状态色只用于 Badge、图标、小面积提示、状态文字，**不要让整张卡片变成鲜艳颜色**。

## 4. 页面配方

### 4.1 工作台首页（默认首页）
`页面标题` → `系统状态` → `3～5 个统计卡片` → `核心待办（最突出）` → `最近任务/业务列表` → `最近记录`。
优先级：**待处理 > 异常 > 重要提醒 > 最近记录 > 统计分析**。若用户的主要工作是处理待办，待办列表必须比图表突出。**不要默认加复杂图表。**

统计卡片必须回答"这个数字对用户有什么意义"：主数字 + 一句对比或说明（如 `↑ 较昨日 3`），不设计无意义数字。

### 4.2 业务列表页
`标题 + 操作区` → `筛选/搜索条` → `表格（状态列靠前，操作列最后）` → `分页`。空结果、加载、错误三种状态都要设计（§8）。

### 4.3 详情
默认**右侧抽屉**（450～600px），不要每次开新窗口；业务确实复杂时才用独立页面。抽屉结构：标题 + 关闭 → 内容分组 → 底部操作按钮。信息分组顺序：**基础信息 / 业务信息 / 操作信息 / 备注**，组间用空间、分割线、小标题建立层级，**不要把所有字段堆在一起**。

### 4.4 表单
`标签 + 输入框` 纵向排列，**标签必须清楚，不允许用 Placeholder 代替 Label**。危险操作与保存分开；校验错误就近提示并说明如何修正。

### 4.5 统计 / 图表
医院工作台不是数据大屏。只有趋势、数量变化、分类统计、工作量统计、库存变化这类**确实有助于决策**的场景才用图表；一个数字能说清就优先显示数字。**不要为了视觉效果强行加饼图/折线图/柱状图。**

---

## 5. 信息层级

每个页面必须明确三级信息，且视觉权重不同：

| 层级 | 内容 | 视觉表现 |
|---|---|---|
| 一级 | 用户最需要关注的 | 字号大、对比高 |
| 二级 | 辅助判断的 | 正常字号 |
| 三级 | 细节信息 | 较小、灰色 |

**不允许所有文字同样视觉重量。**

---

## 6. 表格（医院软件的重点组件）

1. **不要塞入所有字段**：只显示用户快速判断所需的信息，其余进详情。
2. **状态列靠前**：`● 待处理 / ● 处理中 / ● 已完成 / ● 异常`。
3. **操作列固定在最右侧**：查看 / 处理 / 编辑 / 更多。
4. **表头简洁**：不用大字号、复杂颜色、厚重背景。
5. 行高 44～52px；列宽按内容权重分配，长文本截断并提供完整查看方式。

示例列序：`状态 | 编号 | 科室 | 时间 | 数量 | 操作`。

---

## 7. 表单与按钮规格

- **按钮三级**：Primary（确认/保存/提交/处理，主色）｜ Secondary（取消/返回/查看，白底边框）｜ Danger（删除/终止/撤销，红色）。
- **每页只允许一个主要操作**：`[取消] [保存]` 是对的；`[保存][提交][确认][完成][继续][下一步]` 全部突出是错的。
- 输入框高亮、禁用、只读、错误四种视觉态要区分；错误的输入框旁给出原因与修正建议。

---

## 8. 状态与反馈（缺一不可）

| 状态 | 要求 |
|---|---|
| 空状态 | 不显示空白页；明确告知当前状态（如"暂无待处理任务 / 当前没有需要处理的业务"），尽可能提供"刷新"按钮 |
| 加载 | 避免整页白屏；优先 Skeleton 或局部 Loading（"正在加载数据…"），加载完成后平滑替换，不大面积闪烁 |
| 错误 | 必须"发生了什么 + 下一步能做什么"："暂时无法获取数据，请检查系统连接后重试。[重新连接]"，禁止只显示 `Error` |
| 系统连接 | 医疗软件常连 HIS / LIS / PACS / 数据库 / API / 内网服务：工作台提供连接状态与最后同步时间（正常 / 连接异常 + 最后成功同步时间 + 重新连接），状态必须一眼可辨 |
| 权限 | 无权限的功能优先隐藏或禁用，**不要"显示后点击报错"**；必须显示时用锁定图标 + 无权限提示 |
| 通知 | 普通通知=右上角轻量提示；重要通知=Toast + Badge；异常=明显但避免持续弹窗；紧急业务按需弹窗。**弹窗不得打断正常工作** |

---

## 9. 实时性、刷新与动画

- 后台数据变化（新增申请、新维修单、新报修、新移库单）时**不刷新整页**：状态更新 → 列表增量更新 → Badge 变化 → 轻量通知。**用户已打开的详情不能因后台刷新而自动关闭。**
- 自动刷新必须避免：页面闪烁、滚动位置跳动、输入框内容丢失、详情关闭、正在编辑的数据被覆盖。优先**静默刷新 + 增量更新**。
- 动画**少、快、轻**：允许页面淡入、Drawer 滑入、Toast 出现、Badge 数字变化、新数据轻微高亮；禁止大面积飞入、长时间动画、高频闪烁、强烈弹跳、炫酷转场。医院软件需要**稳定感**。

---

## 10. 图标与一致性

- 图标统一用一个库（推荐 Lucide，或项目现有库），保持**同一风格、同一线宽、同一视觉尺寸**；**禁止把 Emoji 当成正式 UI 图标**。
- 全项目统一 Design System，至少统一：颜色、字体、字号、圆角、阴影、边框、按钮、输入框、表格、Badge、Drawer、Dialog、Toast、间距、图标。**新增页面不允许出现"每个页面一种风格"。**
- 组件目录建议：`AppShell / Sidebar / Header / StatCard / StatusBadge / DataTable / SearchBar / FilterBar / Drawer / Dialog / EmptyState / LoadingState / ErrorState / Toast / Notification`。
- 状态色语义全产品统一：待处理→橙、处理中→蓝、已完成→绿、异常→红；同一种状态永远同一种颜色。
- 圆角适度圆润即可，**不要整个界面都是巨大圆角**（不要"儿童化"）。

---

## 11. 隐私与长时间使用

- **最小必要信息原则**：不主动显示患者身份证、手机号、地址、无关病历/个人信息，除非业务明确要求；敏感字段脱敏显示（`张**`、`138****1234`）。
- 长时间使用体验：避免纯白高亮、过高对比、过多鲜艳颜色、太小字体、过密布局、频繁弹窗；整体"安静、稳定、耐看"。

---

## 12. 禁止事项（默认全部禁止）

❌ 大面积渐变 ❌ 大面积玻璃拟态 ❌ 过度圆角 ❌ 巨型数字大屏 ❌ 过多动画 ❌ 高频弹窗
❌ Emoji 作为正式图标 ❌ 彩虹色 UI ❌ 无意义的数据图表 ❌ 密集堆砌功能
❌ 小于 12px 的大量正文 ❌ 把所有功能塞到首页 ❌ 为了"高级感"增加复杂视觉效果
❌ 状态色污染整块卡片 ❌ 一个页面多个 Primary 按钮 ❌ 弹窗打断正常工作 ❌ 显示后点击报错的权限设计

除用户明确要求，**不要自行改成深色科技风**。用户未指定风格时，默认采用 **Modern Medical Desktop Workspace**：浅灰背景、白卡片、医疗蓝主色、轻边框、轻阴影、8～12px 圆角、14px 正文、清晰表格、克制状态色、左侧导航、顶部状态栏、工作台首页。

---

## 13. 交付前自检

逐条核对：
1. 外壳：左导航 210～240px / 顶栏 56～68px / 主区留白 24px；一级导航 ≤7 项。
2. Token：颜色、字号、间距、圆角全部来自 §3，无临时值；正文 ≥12px 且未大量使用 12px。
3. 信息层级：一级信息是否最显眼？是否所有文字同样粗细/颜色？
4. 状态：Loading / Empty / Error / Disabled / Permission / Offline 是否都设计了？
5. 交互风险：是否有整页刷新、闪烁、滚动跳动、输入丢失、详情被关、编辑被覆盖？
6. 表格：字段是否精简、状态是否靠前、操作是否在右、行高 44～52px。
7. 详情：是否用抽屉（450～600px）？信息是否分组？
8. 按钮：是否只有一个 Primary？危险操作用红色？
9. 隐私：是否出现非必要的患者身份证/手机号/地址？是否脱敏？
10. 适配：1366×768 下是否仍可用（不出现只有 1920×1080 才正常）？
11. 一致性：新页面与既有页面是否同风格、同组件、同状态色语义？
12. 禁止事项 §12：是否有触碰？

**自动审查**（零依赖 Node 脚本，扫描 HTML/CSS/Vue/JSX/TSX/XAML 源码中的硬编码违规）：

```bash
node "<技能资源基目录>/scripts/ui-audit.mjs" <目标目录或文件...> [--json] [--max-issues=N]
```

它按 §3 / §12 检查：非 token 硬编码色值、小于 12px 字号、过大圆角、渐变与玻璃拟态、Emoji 当图标、`!important` 滥用、表格行高越界、阴影过重、深色科技风背景、非体系间距，输出文件:行号 + 规则号 + 修复建议；`--json` 供 CI 使用。审查结果只作为线索，**必须结合页面语义人工确认后再改**（图表内渐变、注释内符号属合理例外）。

---

## 14. 落地映射

- **Web（HTML/CSS/React/Vue/Tailwind）**：token 变量 → `templates/tokens.css`；组件与布局实现要点见 `references/platform-web.md`。
- **WPF / XAML（桌面客户端，含打包为单文件 exe 的内网部署形态）**：颜色/字体/圆角/间距 → `templates/theme.xaml` 资源字典；控件与布局映射见 `references/platform-wpf.md`。

两种平台的共同约束是同一份 §3 token 与 §12 禁止事项——平台差异只体现在写法，不体现在设计决策。
